# Project Layout

This guide describes the current folders in `Inventory-search` and where each kind of file belongs. It is an organization map; it does not claim that every included sample or old report is required to run the application.

## Main application

- `app_gui.py` — desktop GUI entry point.
- `main.py` — alternate/legacy command-line workflow.
- `src/` — parsing, matching, allocation, report generation, and controller modules.
- `assets/` — application icons and other packaged resources.
- `requirements.txt` — Python dependencies.
- `تشغيل_البرنامج.bat` — Windows launcher for running from source.
- `build_exe.py`, `EgyptianPharmaOptimizer.spec`, and `installer.iss` — executable and installer build configuration.
- `.env` — optional local configuration/secrets; ignored by Git. Do not commit it.

## Documentation

- `README.md` — project overview and setup notes; kept at the root for easy discovery.
- `CHANGELOG.md` — release history; kept at the root because the test suite references it.
- `docs/PROJECT_LAYOUT.md` — this folder map.
- `docs/current/` — current handover, organization, audit, and test documentation moved from the root.
- `docs/` files outside `current/` — existing reference documents retained in place; check dates/content before treating them as current.

## Tests and investigation

- `tests/` — maintained automated tests.
- `diagnostics/` — one-off diagnostic scripts, including `probe_m4.py`; not needed for normal app use.
- `scripts/` — developer and maintenance scripts. Survey JSON reports currently live here alongside scripts.
- `scratch/` — temporary investigation scripts, comparisons, and intermediate data; not needed for normal app use.

## User and sample data

- `input/` — default user input location, with `orders/` and `catalogs/` subfolders.
- `output/` — generated procurement reports and prior report artifacts.
- `test1/` — sample order and supplier catalogs for manual checks.
- `train/` — larger benchmark/training catalog and order set. Preserve unless you know it is no longer needed.
- `test_out/` — generated test run outputs and caches; safe to regenerate only after confirming they are not needed.

## Archive and generated build files

- `archive/` — older backups and the archived `EgyptianPharmaOptimizer_ReadyForWindows` copy; retained for reference.
- `build/`, `dist/`, and `dist_installer/` — generated packaging/build output. These can be regenerated by the build process, but keep the current installer if you distribute it.
- `__pycache__/` and `.pytest_cache/` — generated Python and pytest caches; safe to recreate.
- `.tmp.drivedownload/` and `.tmp.driveupload/` — temporary transfer data; inspect before cleanup.
- `.agents/` — project workflow/agent notes, not required at runtime.
- `.git/` — Git history and metadata; do not remove.

## Sorting choices

Only documentation and the standalone probe were moved in this pass. Application code, sample data, prior reports, archives, and generated build output were left where they were because they may be needed for running, testing, distribution, or historical reference. Review `scratch/`, `test_out/`, caches, and temporary transfer folders before deleting anything.
