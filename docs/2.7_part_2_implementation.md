## Phase 1: Correct old-price ingestion policy

### Scope and predicate

Apply the requested exclusion to Excel purchase orders, Excel supplier catalogs, and Excel average-discount references. Apply the same rule to CSV equivalents already handled by these shared loaders and document this explicitly. Do not expand this change to PDF parsing or PDF search results.

Keep one shared predicate, exposed through `src/order_parser.py` as required. Do not add filename-specific branches to `src/excel_parser.py` or alter `clean_arabic_string` / general matching normalization.

For predicate inspection only:

1. Treat null/NaN and empty values as non-matches.
2. Convert tabs/newlines and other whitespace separators to spaces before removing remaining controls. Remove BOM and directional formatting controls, including Arabic letter mark and directional isolate/embedding controls. Do not join separate words accidentally.
3. Strip only the documented outer `xx...xx` marker convention. Preserve internal Latin letters and the original source name. Define tests for both paired wrappers and the trailing marker form already supported by the reference loader.
4. Match the terminal suffix using actual Python syntax:

```python
OLD_PRICE_SUFFIX_RE = re.compile(r'(?:^|\s)(?:س[\s.]*ق|ق[\s.]*س)\s*$')
```

This requires the start of the string or whitespace before the suffix. Digits, slashes, and hyphens alone are not an accepted boundary. The expression also accepts standalone `سق` / `قس`, consistent with the original guardrail's zero-or-more separator rule; make that behavior explicit in tests.

Never reject `س ج`, `اقراص`, `لاسيكس`, or `زوفيراكس` merely because of their final letters. Do not remove a suffix from the stored name as a substitute for rejecting the row.

### Placement, accounting, and failure handling

- Evaluate raw names before suffix cleanup, canonicalization, deduplication, or quantity aggregation can erase the old-price marker.
- Review each Excel/CSV path, including the average-discount pandas fallback. Avoid redundant scans at several layers when a single authoritative ingestion check suffices.
- Preserve eligible requested-item text and quantities exactly as before. Continue preserving new-price rows.
- Record exclusion reason `old_price_suffix`, source file, sheet/row where available, original name, and excluded quantity when present. Keep per-file counts available to the GUI/report diagnostics.
- Never put excluded order rows into the out-of-stock sheet. Report them as intentionally excluded, distinct from unavailable medicines.
- An all-excluded order produces a clear empty-input outcome and no misleading successful procurement report. Distinguish parse failures from intentional exclusions and surface per-sheet failures instead of silently reporting complete success.
- Empty reference data must return the documented schema; a missing/invalid optional reference must not crash manual catalog search.
- Move bundled reference row-count expectations into fixture-specific tests. Runtime reference validation should check schema and valid records rather than reject legitimate small files because of their basename. Preserve existing discount interpretation and deduplication behavior.
- Do not edit source spreadsheets or the bundled reference file to implement filtering.

## Phase 2: Manual-search integration without algorithm changes

### Service boundary

Locate and reuse the current search/matching entry point through a thin, independently testable adapter. The adapter handles input snapshots and result presentation; it must not implement a replacement scorer, fuzzy fallback, token matcher, transliteration, or new relevance ordering.

If the existing API cannot expose manual-search candidates, document that integration limitation. Do not substitute the earlier proposed ranking algorithm. An additive wrapper is acceptable only if it invokes existing logic without changing its behavior; otherwise defer that dependent capability and identify the exact decision required.

### Catalog scope and provenance

- Snapshot `file_model.get_catalog_files()` on the GUI thread. Normalize/deduplicate paths and resolve only those active sources through validated cache access.
- Use `global_catalog_cache.get(path)` / `inspect_catalog(path, refresh=False)` in the background as appropriate; do not union every cached source into the active selection.
- Read `CatalogResult.dataframe` explicitly and preserve diagnostics, source IDs, review status, and fingerprints before combining rows. Do not rely on DataFrame attributes surviving concatenation.
- Exclude rejected/unprocessed and unresolved-review rows using the existing eligibility rules. Preserve partial-import acknowledgment behavior; opening search must not mark a catalog accepted for procurement.
- Show out-of-stock or unknown fields accurately if the existing search API exposes them; never present such rows as confirmed purchasable offers.
- Maintain an immutable snapshot per search generation. Removing/changing a catalog or applying corrections invalidates the window snapshot and outstanding results.
- Prevent duplicate offers introduced by loading the same source twice. Do not collapse legitimate distinct supplier/pack/price offers by medication name.

### Threading and window lifecycle

1. Add toolbar/sidebar launchers consistent with existing UI layout. Compute grid placement from current code rather than blindly shifting hardcoded column numbers.
2. Use a single reusable `CTkToplevel`, transient to the app; focus an existing window on repeated clicks. Keep it non-blocking so catalog selection remains accessible.
3. Keep every Tk operation on the GUI thread, including StringVar reads, `after`, widget updates, and destruction.
4. Debounce input with a 60 ms GUI-thread timer. Debouncing delays work; it does not make synchronous work non-blocking.
5. Run catalog inspection, reference loading, indexing/adaptation, and existing search calls outside the GUI thread. Verify thread safety; serialize access to shared parser/search state where necessary without changing algorithms.
6. Use a bounded worker queue: at most one active job and one replaceable pending query per window. Superseded input must not create an unbounded backlog.
7. Return plain results/errors through a thread-safe queue. A GUI-thread polling callback consumes them. Workers must not call Tk, including `after`.
8. Tag jobs with query, filter, and catalog generation IDs. Display only results matching the latest generation.
9. Cancel debounce/poll callbacks and invalidate pending jobs on close. Do not block the GUI on worker shutdown; ignore late completions and release resources cooperatively.
10. Provide loading, no catalogs, no matches, partial failure, and retry states. A failed catalog/reference must be visible and must not masquerade as a valid empty result.

### Display contract

| Field | Contract |
|---|---|
| Medicine | Original display name; retain strength, form, pack and pricing state |
| Wholesaler | Verified source warehouse; preserve provenance |
| Public price | Valid `base_price`, otherwise an unknown marker |
| Discount | `100 * discount_rate` percent; do not infer or double-convert units |
| Net price | `base_price * (1 - discount_rate)` only when both inputs are valid |
| Reference weighted discount | Separate labelled reference value, never a supplier offer |
| Availability / review | Truthful existing status; no invented availability |

Keep reference-only results in a separate view or clearly separated section. They have no confirmed supplier, net price, or stock. Match references only via an existing supported lookup; missing lookup support must not lead to a new matching algorithm.

Preserve existing relevance order in Best Match mode. Highest Discount is an explicit display sort over candidates already returned by the existing search, not a new matching rule. Apply warehouse scope before search through a supported input mechanism; apply display sort before the 100-row rendering cap. If the existing API truncates candidates, disclose that limit and do not claim a global highest discount. Blank-query browsing is presentation-only over eligible selected offers.
